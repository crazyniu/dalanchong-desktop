# 本地数据库

桌面端的达人采集、邀约记录、任务摘要、采集批次、账号配置和日志统一保存在 `<应用数据目录>/assistant-data/assistant.sqlite3`。SQLite 随软件内置，数据保留在本机。

使用 `sh ./run.sh` 时，数据库位于 `../.local/ecommerce-assistant/assistant-data/assistant.sqlite3`。该目录包含真实业务数据，不能作为构建缓存删除，也不能放进源码仓库或安装包。

## 数据读写

- 每批采集只新增或更新对应达人，按平台、来源账号和达人身份去重；同一账号的 UID 关联保持既有达人 ID，确保邀约历史仍能匹配。
- `invite_ids` 在批量筛选或所选范围内，按 `platform + accountId + talentId` 查询无邀约记录的达人 ID。两平台均排除已有 `success`、`skipped`、`failed`、`review` 或 `sending` 记录者，不按日期限制；仅主动清除对应记录后，该记录不再阻止入队。该查询只用于邀约候选，不改变列表筛选、导出或删除范围。
- 每条邀约发送前先提交 `sending` 记录，收到结果后更新该记录；启动时将未取得最终结果的发送记录标记为待核实，不自动重发。
- 任务摘要按账号与任务类型分别保存，同一账号的采集与邀约可以同时运行，各自更新和停止。主界面任务键为 `accountId:kind`；数据库账号字段仍保存真实账号 ID，任一任务运行期间保留该账号的数据删除限制。
- 采集列表、邀约记录和错误日志按账号及筛选条件查询当前页。邀约记录列表及采集列表的最近邀约摘要不包含完整响应正文，邀约详情打开后按记录 ID 读取完整记录；错误日志当前页包含已保存的响应详情。
- 数据概览由数据库汇总当前范围，日期边界使用界面的本地日期；采集人数仍只计现有账号中当前保留的达人。
- 正常采集活动与错误日志均写入日志表。采集终端展示当前采集任务最近 200 条活动，重启时只为现有账号分别恢复最近采集、邀约任务已保存的活动与错误摘要，各最多 200 条；日志按账号、任务类型和启动时间归属，已移除账号的数据库历史保留。错误日志界面只查询异常记录，清空与导出仍限定当前账号。
- CSV 和日志导出由用户选择保存位置后写入文件。导出文件不是业务存储，取消保存不会提示成功。

## 首次导入

首次打开数据库时，在事务中导入同一数据目录已有的运行数据和错误日志，记录导入完成状态；之后启动不重复导入。原始文件保留作备份，后续业务写入只提交数据库。导入失败时不提交半份数据，原文件保持不变。

导入按原平台、账号和达人 ID 保留记录，即使不同历史 ID 共用同一 UID 也不合并，邀约历史关联保持不变。任务摘要中的日志副本与全局日志匹配时保留原日志 ID，并补齐任务关联；不同响应及独立重复事件继续保留。

数据库读写由原生端处理，主界面持有分页结果、任务进度和必要汇总。查询、导出与删除命令检查主界面来源和原生授权状态；任务停止、收尾保存与异常记录保持可用。

数据库结构版本为 2，`tasks` 使用 `(account_id, kind)` 联合主键。已有数据库在事务中升级，保留任务摘要、真实账号 ID 和日志关联。

Cookie、激活码缓存和独立 Chrome 账号的浏览器数据继续由各自模块管理；数据库不替代系统浏览器会话，也不保存可绕过联网授权的有效性标记。

本次迁移会在用户运行更新后的程序时执行。源码修改不代表已导入本机数据或完成用户验收；测试与验收由用户负责。
