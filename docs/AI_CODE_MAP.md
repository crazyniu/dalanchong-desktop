# AI Repository Navigation Map

Choose the owning file here, then read its in-file English map before editing. This covers the desktop repository and its maintained browser-extension video plugin; the sibling invitation extension and license-admin projects are separate systems. Start with [AGENTS.md](../AGENTS.md) for task splitting, parallel-agent ownership, UI rules, and user-owned acceptance. The annotation contract is [CODING.md](CODING.md); the documentation and directory index is [README.md](../README.md).

## Runtime ownership

```text
src-tauri/src/main.rs -> lib.rs -> managed native services and IPC handlers
index.html -> src/main.tsx -> LicenseGate -> AppShell -> feature route
commerce/desktop.ts -> desktop-runtime/index.ts -> runtime.mjs -> runner.mjs
runtime.mjs -> platform.mjs -> browser::platform_eval -> account WebView
injected page bridge -> platform_result/platform_observe -> native caller checks
native events -> runtime/store -> feature UI -> floating toolbar/log child views
chrome.rs -> chrome_runtime.rs -> installed Google Chrome Stable / isolated account profiles
chrome.rs -> browser_extension.rs -> fixed extension path/ID -> browser-level Extensions API -> video extension UI
package.json.version -> sync-video-extension-version.mjs -> browser-extension/manifest.json
scripts/package.mjs -> prepare-video-extension.mjs -> version sync / packaged extension snapshot
```

## Strict JSON annotations

These files intentionally have no literal comments. Their parsers/schemas consume JSON. Use this per-file map rather than comment syntax or unsupported metadata keys.

| File | Consumer and purpose | Constraints |
| --- | --- | --- |

## Change propagation

Performance ownership is summarized in [PERFORMANCE.md](PERFORMANCE.md). Runtime
events carry compact `Partial<RuntimeData>` domains or one account's `task`;
initialization loads metadata, task summaries and account counts. Database writes
notify mounted views through dataRevision rather than replaying full histories.
Account removal releases live task/replay references; startup loads
task activity windows only for retained accounts while leaving historical rows intact.
Batch writes reuse prepared statements, talent pages select rows and latest-invite
summaries together, and record exports resolve account names once per export.
Treat detached event payloads as read-only and discard stale query results when
filters or accounts change. Each data-query hook permits one in-flight request and
one latest pending request; same-key completed data remains publishable under
continuous revision changes. Closed dialogs do not query datasets. Keep
durable pre-send saves separate from display updates. Native presentation caches
track browser geometry, toolbar content, and task overlays independently; reset
page/toolbar/collection caches when covering the native page while retaining the global invitation overlay. Media capture batches changed DOM subtrees;
passive repeats skip identical writes, while explicit analysis refreshes the
record for the requested work. Commerce media cache callers share
startup restoration and coalesce writes. Extension download progress replaces
only the affected progress controls and permits one in-flight poll per job.
Route modules and update Markdown load on demand. Native invitation progress
contains display fields only. The page-local Douyin send SDK is acquired once,
but device context is read for every send. Library readers share normalization
with the media write queue; stale metadata probes cannot overwrite recaptured
URLs or newer verified sizes. Selection-only media actions retain their row DOM.
LIST_LIBRARY returns schemaVersion 1 with items, jobs and pendingSources. Popup
and manager use ui.js::readLibrary before assigning snapshot fields. A mismatched
worker schema shows an explicit reload action, never an automatic extension restart.
Native overlay geometry updates move incoming state and build payloads only for
changed presentation/content. Superseded page-response readers cancel only their
observation copy. Collection snapshots copy filters while sharing immutable responses;
invitation candidate SQL excludes all existing records for the same platform, accountId,
and talentId before queue creation, regardless of status or age. The runner stops before
another batch once its invite limit is reached.
Hot replacement disposes the old React roots, store listener and demo timers.
Account removal releases form preferences as well as ephemeral task/capture references.
Queued saves read preferences at execution; account removal publishes its cleaned,
latest preference state inside the successful queue item before another save starts.
Only the actual native commit advances the reference baseline, so concurrent changes
to other accounts remain eligible for the next write.
Update installation and activation-cache writes run on blocking workers; installers
share the downloaded archive and retain the storage guard and retry data.
Extension metadata probes follow displayed formats and stop on hidden/cleared views.
HLS preview loads its module on demand and uses the preview revision for import and
refresh results. Douyin document caches retain download fields only.
