# 激活码接入

## 使用

1. 在 `license-admin` 后台选择「大懒虫」，软件标识必须是 `dalanchong`。
2. 创建所需时长的激活码，复制给用户。
3. 启动桌面端，输入激活码并点击「激活」。点击侧栏左下角的到期日期或「永久有效」查看激活信息，只显示到期时间与设备码。
4. 换电脑时先在后台对该码执行「解绑换机」，再在新电脑激活。首次激活时间和原到期时间保留。

激活需要联网；后台查询失败后暂停受限功能，恢复联网后由下一次后台查询恢复授权状态。后台解绑后不会自动重绑，需手动输入激活码激活。软件没有管理员登录入口，不需要管理员账号密码。

## 固定配置

- 软件：大懒虫
- `app_id`：`dalanchong`，沿用后台已有记录，不得改成包名。
- 接口：`https://dabudian.top/functions/v1/license-api`
- 自定义域名由 Cloudflare 转发至授权服务，客户端不直接连接 Supabase。
- `POST /activate`、`POST /verify` 请求体：`{ app_id, code, device_id }`。
- 公共接口不需要 Supabase 管理员凭据或服务端密钥；详细协议见 [授权接口文档](https://github.com/crazyniu/license-admin/blob/main/docs/API.md)。

## 运行流程

Rust 后台在启动时完成首次授权查询，此后每 10 分钟查询一次。`LicenseGate` 只读取和订阅原生授权结果，首次查询期间居中显示加载状态，成功后才载入业务数据与页面。未激活、过期、设备被禁用、设备不符或联网失败时显示激活页。

Rust command 保留 main 来源校验。弹框、业务操作和平台请求只读取最近的原生内存授权结果，不调用 `/verify`；状态读取与后台网络请求使用独立锁，不等待联网。后台结果无效时，平台请求在发送前抛出 `beforeSend` 错误，任务停止，不把尚未发出的邀请标记成已发送或待核实。停止任务不受授权限制；在途平台请求沿用任务原有结果处理。

打开本机 Chrome 账号属于受限的桌面操作，由 Rust 校验调用来源并读取后台授权结果。视频插件使用自身 Chrome 扩展 API 和对应账号的浏览器会话，不拥有 Tauri 本机数据、授权或更新权限。

保存过激活码时，后台每 10 分钟调用一次 `/verify`，闲置或授权无效时也按该间隔执行；服务器返回过期、解绑、禁用或查询失败后，停止采集和邀约并显示激活页。时间和有效性由服务器判断，不依赖修改电脑时间。重新查询恢复有效后回到业务页面，已停止任务不会自动重启。退出重启由后台重新查询，不重新激活或续期；查询失败不会自动调用 `/activate`。提交激活码由 `/activate` 处理。

激活码只在成功激活后保存。输错替换码保留旧码。设备码由 Rust 原生端从硬件 UUID 生成；断网也能查看和复制。授权时间取服务端返回值，界面按本地时区显示，永久授权的 `expires_at` 为 `null`。

## 硬件绑定

- macOS 通过 IOKit 读取 `IOPlatformUUID`；Windows 通过 `GetSystemFirmwareTable` 读取 SMBIOS Type 1 硬件 UUID，不执行外部命令，不使用可复制的安装 UUID 或注册表 MachineGuid。
- 硬件 UUID 以 `dalanchong:hardware:v1`、系统名称为固定域做 SHA-256 摘要，生成 `hw-v1-<64 位小写十六进制摘要>` 中间字符串，再对完整字符串取 MD5。最终设备码为 32 位小写十六进制，界面显示、复制、激活和校验请求共用同一个值。两次处理均为不可逆摘要；原始 UUID 不写入缓存、日志或接口。
- 每次启动从系统重新读取，授权请求只使用 Rust 内部生成的设备码。修改缓存、复制数据目录或修改前端显示不会改变请求中的设备码。读取失败、全零或全 FF UUID 时拒绝激活和使用，显示硬件设备码读取错误，不退回随机 ID。
- 硬件 UUID 不变时，重装软件、清缓存、换数据目录均保持同一设备码；更换主板或改变虚拟机硬件 UUID 会被视为新设备。系统报告的硬件 UUID 本身需唯一；虚拟机克隆、固件伪造或修改原生程序不属于此轻量方案能绝对防止的范围。
- 服务端 `license_access` 锁定激活码记录后检查唯一 `device_id`；同一码并发首次激活时只有首个设备能绑定。已绑定时，其他设备的激活与验证都返回 `device_mismatch`，原设备离线也不开放换绑。验证接口不会创建新绑定。

系统接口依据：[Apple IOKit 设备 UUID](https://developer.apple.com/documentation/iokit/kioplatformuuidkey)、[Microsoft 固件表接口](https://learn.microsoft.com/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemfirmwaretable)。

## 本机数据

`<应用数据目录>/assistant-data/license-tauri.json` 只保存激活码；macOS 本地文件权限为 0600。设备码在启动时从硬件生成，授权有效性由 Rust 联网校验。前端不能读取本地保存的激活码。

`sh ./run.sh` 默认使用 `../.local/ecommerce-assistant`，与已有账号数据共用同一目录。单独 `pnpm desktop` 使用 `<appData>/电商助手` 目录。两种方式及 `ASSISTANT_TEST_DATA` 隔离目录在同一台电脑上得到相同的硬件设备码，账号数据仍按各自目录隔离；请日常统一用 `run.sh`。

上述目录包含真实账号与授权缓存，不入 Git，也不是清理构建产物时可删除的临时目录。更新签名私钥另外保存在 `.local/tauri-signing/`，与激活码缓存不同，保留规则见 [发布说明](RELEASE.md)。

浏览器 `pnpm dev` 使用演示模式，不调用真实平台或授权接口。Tauri 开发和生产构建均启用授权，不能用环境变量跳过。

正式版的主界面、平台网页、工具栏和日志浮层显式关闭开发者工具；开发版保留调试能力。授权沿用现有在线接口与本地缓存，不引入加壳、复杂反调试或新的授权凭证体系；这些限制提高修改成本，不保证客户端无法被逆向。

## 维护与验收

授权失败按请求超时、连接失败、HTTP 错误状态、响应接收失败和响应格式错误分别提示，不把服务端错误统一归为网络故障。收到非成功 HTTP 响应时直接显示状态码。

激活页在有诊断信息的错误下提供「复制错误详情」，复制本次请求时间、激活或校验操作、接口地址、失败阶段、底层错误、实际收到的 HTTP 状态和请求编号，以及软件版本、操作系统。连接失败且未收到响应时没有 HTTP 状态；已收到响应头后再发生超时或解析错误时保留状态和请求编号，方便区分失败阶段。诊断只在内存中保存，不包含激活码、设备码、请求体、响应正文或凭据，不新增联网探测或自动重试。

代码风格、必要注释和授权维护边界统一见 [代码规范](CODING.md)。当前实现包含硬件摘要绑定、后台每 10 分钟授权查询、原生内存结果约束和正式版关闭开发者工具；实现完成不代表已完成真实设备验收。

测试与验收由用户负责。需要联调时使用临时测试码与隔离数据目录；隔离目录不会改变硬件设备码，禁止以「禁用当前设备」测试影响本机已有授权。异设备拒绝行为需要另一台电脑。不要触碰用户已有激活码或真实账号数据。
