# 桌面端性能实现

本文记录当前代码的性能处理和保留边界，不代表运行时测速或用户验收结果。测试与验收由用户负责。

## 网页与原生浮层

- 路由页面按需载入，授权页面不提前加载数据概览图表；更新说明按打开需要载入，下载进度变化复用已渲染的 Markdown。
- `src/features/commerce/browser.tsx` 分别同步网页位置、工具栏内容和任务浮层内容。账号、尺寸或可见性没有变化时，不重复获取原生窗口尺寸或调用网页显示接口。
- 原生邀约进度只传输显示所需的计数和当前达人，不携带任务日志、响应正文和采集筛选配置。网页几何测量忽略无关滚动，弹框内的表格更新不触发遮挡层扫描；移除账号同时释放对应的前端网页、会话和截图引用。
- 网页区域的尺寸测量合并到动画帧；遮挡层监听只响应相关弹框节点的挂载和卸载。网页背景截图与工具栏、采集终端隐藏并行处理；全局邀约浮层持续显示，解码背景提交后再隐藏原生网页并挂载弹框。遮挡期间复用本次内存背景，关闭后释放。macOS 通过 CGImage 转为位图后编码 JPEG，省去 TIFF 中转；Windows 同样使用 JPEG，减少跨进程图片传输与解码数据量。
- 桌面主页面只同步原生工具栏和任务浮层，不再额外绘制一份被原生网页盖住的相同内容。浏览器预览仍使用 DOM 组件。
- 原生日志浮层通过 `response-details.tsx` 引用纯展示的接口详情，不加载主页面的业务状态、任务运行时或平台监听器。
- `toolbar.rs`、`overlay.rs` 各保留一个浮层 WebView。工具栏与采集终端在弹框覆盖和切换账号时隐藏、更新内容后恢复；全局邀约状态使用稳定的展示标识，跨菜单、平台、账号和弹框持续可见，并优先于采集终端。首次显示与恢复由界面提交尺寸后确认；原生端调整同父视图顺序，保证复用浮层位于账号网页之上且不抢焦点。旧显示周期的尺寸和操作消息不会影响当前展示。
- 普通任务进度不重显浮层，未变化的位置、尺寸和内容不重复同步；拖动位移合并发送。工具栏拖动位置及同一采集卡在弹框覆盖期间的收起、滚动状态保留。两个浮层常驻且不新增轮询；账号网页继续保留独立会话，隐藏不停止正在运行的任务。
- 原生浮层直接接收传入状态，只有展示内容变化时才生成事件数据；单纯调整位置和尺寸不复制整份采集日志。
- `page-bridge.js` 只处理已适配接口，过期响应及应用自身请求不额外复制响应流；响应脱敏减少重复 JSON 转换。原生观察事件直接序列化已脱敏字段，不再把大响应正文复制到中间 JSON 对象。路由与观察回调继续使用同一串行队列。
- 原生平台结果回调异步解码；观察响应先判断文档、路由和请求序列，再解析仍然有效的正文。网页截图直接编码进最终 data URL，减少一份完整 base64 字符串的分配与复制。
- 网页观察响应在分块读取期间再次检查是否过期；过期时取消观察副本，不继续读取和拼接完整正文，平台自身的响应保持原样。

## 数据与任务

- `runtime.mjs` 初始化读取账号配置、任务摘要和账号采集数量等小型状态。任务事件只包含当前账号的一类任务，采集与邀约以账号和类型分别保存，可同时运行且独立停止，数据库变更通过版本通知刷新已打开的查询视图，不将全部达人和邀约历史复制到界面状态。
- `store.ts` 仅在持久化字段发生变化时写入本地偏好。任务进度和网页捕获状态不触发无关的同步 localStorage 写入。运行时在保存队列执行时读取最新配置，按最后成功提交的配置引用比较，只向 SQLite 提交发生变化的账号和配置字段。
- 额度分组按业务字段比较，相同额度响应不因数组引用变化而重新保存账号。抖音发送 SDK 每个网页文档只获取一次，设备信息仍逐次读取，避免长任务反复注册相同模块。
- 采集按批次更新数据库中的达人记录，使用平台、账号、达人 ID 和 UID 索引去重。邀约先通过数据库 `invite_ids` 从本次筛选或所选范围中取得当前账号无邀约记录的达人 ID，再分批读取这些新候选；历史记录不进入本次队列或跳过计数。
- 采集启动仅复制可变的筛选参数，复用只读观察响应。邀约候选查询按平台、账号和达人 ID 排除所有已有记录，不限状态与日期；达到本次邀约上限后立即退出，不额外读取下一批达人。
- 采集分页循环只保留已见达人 ID 用于计数，不额外积累全部达人对象。每个已启用的数据库查询最多保留一个在途请求和一个最新待查请求；数据变化直接调度查询，结果返回后更新界面，停用后解除订阅。快速输入不会堆积全部中间查询，持续采集时同参数的已完成结果仍能显示。
- 网页工作区只订阅当前账号数量和运行状态，全局邀约状态卡独立订阅全部平台运行中的邀约任务。采集列表、邀约记录和错误日志由数据库筛选、排序和分页，界面只读取当前页；来源选项和可选列仍按当前账号全部采集数据计算。邀约记录和采集列表的最近邀约摘要不带完整响应，邀约详情按 ID 读取；错误日志当前页包含已保存的响应详情。
- 数据概览在数据库中汇总计数和趋势，只返回指标与日期桶；日期桶由界面按本地日期生成开始和结束时间，保持现有统计口径。
- 邀约候选快照只复制发送需要的身份与来源字段；成功接口响应的脱敏复用已经解析的数据，避免重复解析商品等大响应。
- 正常采集活动和错误日志均增量写入数据库；采集终端仅在界面保留当前采集任务最近 200 条活动，重启可从日志表恢复账号各类最近任务的活动与错误摘要，各最多 200 条。错误日志按当前账号分页读取。
- 初始化只缓存完成状态，再次授权后从当前状态恢复页面。任务结束在释放任务登记后统一发送完成事件。移除账号后释放运行任务和事件回放中的该账号引用；启动只恢复现有账号的任务及其活动窗口，已移除账号的数据库历史继续保留。
- 邀约表单只订阅展示所需的进度字段。全局进度卡直接由运行中的邀约任务派生，全部任务完成或停止后隐藏；采集列表跨页取消勾选使用集合查找。
- 清空错误日志只发布实际受影响的任务；任务启动失败的收尾始终释放本地任务占用。删除账号在保存队列内提交并同步清理其表单配置和瞬时任务引用，再放行后续保存，避免旧配置写回；发布时保留其他账号期间产生的新状态。界面同步清理选择状态，数据库中的达人与邀约历史继续保留。
- 表格时间显示复用日期格式器；小型 CSV 导出逐行生成文本，省去全量单元格中间数组。固定展开侧栏不挂载隐藏提示框，固定主题不监听系统配色变化。
- 开发热更新释放旧的业务订阅、演示计时器和 React 根节点；浮层卸载后不再发起初始握手。正式任务仍由运行时独立管理。

## 原生读写

- 业务数据位于 `assistant-data/assistant.sqlite3`。数据库迁移、事务读写、分页与统计查询在原生阻塞任务中执行；采集更新和邀约状态只提交本次变更，保存开销不包含全部历史数据。原数据导入和保留规则见 [本地数据库](DATABASE.md)。
- 采集列表和邀约记录的 CSV 由原生端按查询范围读取并逐行写出，不把全部导出记录传到前端。数据概览仅导出当前日期范围的小型汇总表。
- 现有串行存储锁复用一条 SQLite 连接，避免每次查询和写入重新开关数据库及设置 WAL。分页参数绑定，读写语句缓存跨操作保留；采集列表在一次分页查询中读取达人与最近邀约，减少重复排序和关联。邀约记录导出预先建立账号名称映射，不逐条解析账号名单。
- Cookie 快照内容未变化时不重复落盘，直接序列化字符串数组，读取、写入和删除文件交给阻塞线程；仅成功写入后更新快照缓存与保存时间。账号目录和现有登录数据保留。
- 授权由后台启动时及每 10 分钟统一查询；业务操作只读取独立锁中的最近原生结果，不触发网络请求，也不等待后台网络锁。授权状态没有变化时不重复广播界面事件；下载更新进度合并通知，最终状态仍立即发布。
- 激活缓存写盘、店铺删除时的账号文件处理和更新安装使用阻塞线程；激活仍先落盘再发布成功。安装共享已下载的更新包，不复制整包字节；安装失败保留现有重试数据。

## 浏览器视频插件

- 抖音及已适配电商页面的视频扫描按变化的 DOM 子树批量处理，播放事件只扫描对应播放器；资源监听处理新条目，只有明确重新扫描时才重读资源列表。
- 网络响应先按类型和大小筛选，再查询来源标签页，普通图片、脚本、样式不触发无关存储查询。重复的视频分段响应不重写相同媒体记录；明确重新解析仍刷新观察时间。
- 抖音作品解析只返回当前作品的详情结果，页面推荐流不混入该作品。视频响应类型可直接确认媒体；仅地址候选和二进制响应需要读取有限文件头，不将图片、音频或接口返回当作视频展示。
- 媒体缓存启动读取由所有调用共享，清空与写入等待读取完成；突发写入串行合并，无媒体的标签页关闭不重写缓存。列表读取串行合并，避免多次存储事件发起并行全量读取。
- 弹窗和管理页共享后台同一次媒体库读取，记录规范化与清空进入同一写入队列；比较变化字段时不把整份媒体记录重复转成 JSON。清空列表同时取消尚未开始的大小探测，旧 URL 的探测结果不覆盖新地址或已验证大小。
- 下载进度仅更新相关行的进度控件，保留选择框、画质控件和其他行；最近下载任务使用索引查询。
- 选择、全选及取消选择复用已有行；管理页每次媒体渲染只计算一次分组。徽标计数不再为各组格式排序，批量分轨下载按来源一次建立音轨索引。
- 网页内电商批量下载最多同时提交 3 个请求，按实际处理数量更新进度；提交成功显示下载任务已创建，不代表文件已落盘。请求结束清理消息监听和超时计时器，关闭弹框释放其选择事件监听。
- 浏览器下载进度每个任务最多保留一次在途查询，完成后停止轮询，避免查询耗时超过间隔时积压。
- 分辨率探测完成时清理全部媒体事件监听，再释放播放器资源，避免同一次探测重复结束和重复调度。
- 筛选、清空媒体列表时，取消不再展示的分辨率探测和排队请求；取消不写入失败缓存，重新展示时可以正常探测。
- HLS 播放模块仅在首次预览对应视频时加载；关闭或切换预览会使旧加载请求失效，旧视频的重新解析结果也不会覆盖新预览。
- 流式下载每积累约 4 MiB 字节便转为 Blob 分块，释放已处理的 JavaScript 字节数组。HLS 下载阶段以 Blob 保存已完成分段，减少完整视频常驻 JavaScript ArrayBuffer 的开销；本地封装仍由 FFmpeg 处理。抖音网页详情缓存保留最近 100 个作品的下载字段，不保存整份作者、推荐及图文响应；已保存的媒体库记录不受此缓存上限影响。

## 保留边界

正式邀约仍串行发送，发送前先提交 `sending` 记录的数据库事务，结果不确定时转为待核实并停止。发送前耐久保存、后台授权结果约束、账号隔离及响应脱敏均保留。

打开弹框需要完成网页截图、解码和原生隐藏，耗时取决于系统 WebView 和设备负载，不等待授权网络查询。Google Chrome 使用原生硬件与媒体能力。第三方网页本身、网络和设备负载仍需由实际使用反馈区分。
